Frozen 2026-10-26, before any gate run. Amendments are appended below, dated, and the file is re-hashed.
Rules followed: Verdict Gates v2 (class-shaped; near-tie flips are documented, not auto-kills; paired forms
decide; a perfect candidate must PASS, garbage must FAIL) and the tolerance doctrine (the change is a
numerics-changing class: a new code path, judged against llama.cpp with a declared tolerance, not by byte
parity). One development smoke run happened before this freeze: a 4-layer 16-expert tiny file, 8 greedy
tokens, identical to llama.cpp. It is not in the gate set.

## Arms and positions

- R (reference, the oracle): llama.cpp CPU greedy (`ref_greedy`, n_gpu_layers 0), 64 tokens, top-5 logits at
  the prompt end and after each generated token.
- C (candidate): this engine, exact tier (no `LLB_PREFILL`, no `LLB_Q4_DP4A`). Greedy run: 64 steps. TF run:
  prompt + R's first 63 generated ids, its `logits` line at each of those 64 positions (top-1, top-2).
- F (floor): llama.cpp CUDA (`ref_tf`, n_gpu_layers 99) on the same 64 TF positions, top-5.
- Prompts (ids < 8192): P1 `760 511 314 938 369`, P2 `774 264 2716 3170 883 279 1741 13`, P3 `727 731 1393 1590`.
  P = 3 x 64 = 192 TF positions a file.

## Definitions

- marg_R(p) = R's top-1 minus top-2 logit. marg_F(p) = F's logit of R's top-1 minus F's logit of R's top-2
  (positions where both are in F's top-5).
- m = max(0.01, 2 x rms_p(marg_F(p) - marg_R(p))): the field's own numeric spread on this file (V-FLIP's
  m_model construction, measured per file).
- Near-tie disagreement at p: C top-1 != R top-1, marg_R(p) < m, and C's top-1 is in R's top-3.

## Gates (per file)

- **G-A (task literal):** every TF disagreement of C with R is a near-tie. Reported with it: greedy agreement
  length per prompt and whether the first greedy divergence is a near-tie.
- **G-B (v2 paired forms; decide when G-A fails):**
  - V-T1: D = mean_p(agree_C - agree_F), agree = top-1 equals R's; paired bootstrap over positions (10,000
    resamples, seed 0); PASS iff CI90 lower bound >= -2.0 points.
  - V-FLIP: hC = C disagreements with marg_R >= m, hF = F disagreements with marg_R >= m; b = #(hC and not hF),
    c = #(not hC and hF); FAIL iff b + c > 0 and P(Bin(b + c, 1/2) >= b) < 0.0125.
- **File verdict:** PASS iff G-A passes; else PASS (v2) iff V-T1 passes and V-FLIP does not fail, with every
  flip listed (position, margin, ranks); else FAIL.
- **MoE verdict:** PASS iff every file passes.

## Controls (must behave, else the instrument is broken and no verdict is called)

- Perfect: F scored as the candidate on S35 Q4_K_M must PASS.
- Garbage: a scratch-only mutant build whose top-k takes the k LOWEST-probability experts must FAIL on S35
  Q4_K_M. (A second mutant, no renormalization of the k weights, is run for information only.)

## Regressions (no new tolerance: byte identity)

- G-REG: 0.8B, 2B, 9B Q4_K_M and clef-flash Q4_K_S, base build vs candidate: prompts `760 6511 314 9338 369`,
  `7734 264 2716 31708 883 279 17415 13`, `727 73111 1393 1590`, 64 steps, tiers exact and `LLB_Q4_DP4A=9`, plus
  `LLB_PREFILL=fast` on the second prompt. PASS iff stdout and every stderr `logits` line are byte-identical in
  every run. The 27B is not run.
- G-SIDE: `gguf2pack --sidecar-only` of those four dense GGUFs, base vs candidate binary: manifest.json and
  table.bin byte-identical.

## Refusals (each must exit non-zero naming the field or tensor)

F32 experts (existing `synth-moe.gguf`), expert ff 128 (not a multiple of 256), expert_used_count 65,
expert_count 5000, `--emit` on a MoE file. `LLB_PREFILL=fast` on a MoE file must run the exact tier and say so.

## Amendment 1 — 2026-10-26, after the first gate file (S512 Q8_0), before any other gate file

Disclosed as post-hoc: written after S512 Q8_0 scored FAIL as frozen (G-A 38 disagreements, 5 high-margin;
V-T1 D -7.29 pt, CI90 [-12.50, -2.08]). A diagnostic run on that file, X = llama.cpp CPU (op offload off) on
the same GGUF dequantized to F32 (`deq_gguf.py`, exact dequantization, so llama.cpp computes without
quantizing activations), gave: C top-1 = X 192/192 with rms(C - X) 0.0002 on X's top-1 logit, while R = X
154/192 (rms 0.343) and F = X 151/192 (rms 0.366). The frozen gate scored llama.cpp's 8-bit activation
rounding (shared by R and F, which makes F track R) as candidate error. The brief names this arm ("also compare
against the same weights dequantized to F32 if needed"); the frozen file omitted it. The frozen gates stay and
are reported for every file. Added:

- **G-X** (where the F32 copy fits on disk: S512 and S60, both formats; S35 and S128F need 6 to 13.5 GB of F32
  and are not run): PASS iff (i) rms_p(C - X) <= rms_p(R - X) on X's top-1 logit (error vs fp32 no worse than
  the oracle's own, the v2 class-3 criterion) and (ii) every C != X top-1 disagreement has marg_X < 0.05 and
  C's pick in X's top-3.
- **File verdict:** PASS iff the frozen verdict passes, or G-X passes. Where X is not run, the frozen verdict
  stands alone.
- **Controls:** the garbage mutant must also FAIL G-X (on S512 Q8_0, where X exists), in addition to the
  frozen control on S35 Q4_K_M.

## Amendment 2 — 2026-10-26, scope change from the owner, before the final-candidate gate runs

The owner widened the scope mid-run: any qwen35moe (35B-A3B, 122B-A10B, 397B-A17B), no caps sized to this
machine, a working path when the experts do not fit in VRAM. The candidate changed: the expert stacks left the
per-layer Bytes (a 397B layer's stacks exceed the 2 GiB Bytes cap) and are loaded by the host from the GGUF into
one of three residencies (device VRAM; pinned, device-mapped host RAM; or streamed from the mmapped GGUF, the k
chosen experts copied per layer and token), chosen from free VRAM / MemAvailable or forced with
`LLB_MOE_EXPERTS`; `LLB_MOE_VRAM` / `LLB_MOE_RAM` stand in for the free amounts. Expert Q8_0 is read in the
GGUF block layout. The router's 4,096-expert and 64-top-k caps are gone. Results gathered so far on the earlier
candidate are kept as information (receipts `gate-v1`); the verdicts are taken on the final candidate:

- Every gate file is regenerated (seeded generator, same commands) and checked identical to the first run by
  re-running R on prompt 1 (byte-identical JSON required); then R, F and X are reused, C is re-run, and all
  gates (frozen + amendment 1) are re-scored.
- **G-MODE (new):** on every gate file, `LLB_MOE_EXPERTS=host` and `=stream`, and auto with
  `LLB_MOE_VRAM=1000000000 LLB_MOE_RAM=1000000000`, give stdout and every stderr `logits` line byte-identical to
  the device residency, greedy and TF, all 3 prompts. The kernels and bytes are the same, so any difference is
  a bug.
- Controls (mutants) are rebuilt from the final candidate and re-run.
- One test-file construction note: S512's Q5_K_M was quantized with `--token-embedding-type q6_k` (the CUDA
  embedding kernels take Q8_0 / Q4_K / Q6_K; a Q5_K embedding is refused for dense files too). No threshold
  changed.
